# 생성 모델 결정 & 비용 분석

## 모델 결정 — gpt-5.4 확정

### 배경
스펙 기본은 "mini 금지"(약한 모델이 minimal-edit 다중 제약 위반 우려). 하지만 비용을 위해
**경험적으로** mini를 검증: excitement_seeking(ES) 248쌍을 여러 모델로 재생성해 비교.

### 실험 (ES 248쌍, Batch API)
| 버전 | overlap(min) | low_overlap | atten/neg | 비고 |
|---|---|---|---|---|
| ES-5.5 (옛 cue) | 0.70 (0.29) | 1 | 0/0 | 기존 데이터셋(반응형 cue) |
| ES-mini (5.4-mini, 새 cue) | 0.55 (0.11) | **30** | 0/1 | minimal-edit 붕괴 |
| ES-5.4 (새 cue) | 0.54 (0.14) | 16 | 0/0 | 채택 |

### 교란 주의
ES-5.5만 옛 cue라 overlap 0.70이 높게 나옴(옛 cue는 high/low가 같은 setting 공유 →
자연히 높음). 즉 **0.70→0.54 하락은 모델이 아니라 cue 변경 탓**. 공정 비교는 같은 새 cue인
**5.4 vs mini**: overlap 동률이나 **low_overlap 16 vs 30 — 5.4가 붕괴 절반**, 샘플도 깨끗.
(누수 휴리스틱은 문장 verbosity에 교란돼 신뢰 불가 → 모듈 2 분류기로 판정.)

### 결론
- **mini 탈락**: minimal-edit(CAA 핵심 축) 붕괴.
- **gpt-5.4 채택**: mini보다 명확히 우위 + 5.5보다 저렴. `.env GEN_MODEL=gpt-5.4`.
- gpt-5.4는 temperature 커스텀 거부(gpt-5 계열, 기본 1 고정) — 코드가 자동 미전송.
- ES는 5.4+새 cue로 교체. 나머지 5 facet은 검증된 5.5 유지(재생성은 낭비, 혼합은 `gen_model`로 기록).

## 비용 분석

### 실측 토큰 (gpt-5.4 배치, 쌍당)
입력 454 + 출력 46 = **500 토큰/쌍**, **추론 토큰 0**.

### 7,500쌍(= Big Five 전체, 30 facet × 250) 환산
| | 입력 | 출력 |
|---|---|---|
| 쌍 생성(7,500콜) | 3.41M | 0.35M |
| 시나리오(~360콜) | 0.42M | 0.14M |
| **합계** | **~3.83M** | **~0.48M** |

**비용 = 3.83M × (입력단가) + 0.48M × (출력단가)**, Batch면 ×0.5.

### 예시 (단가 가정 — gpt-5.4 실단가로 교체 필요, USD/1M)
| 가정 in/out | 동기 | Batch −50% |
|---|---|---|
| $0.25 / $2 | $1.92 | $0.96 |
| $1.25 / $10 | $9.60 | $4.80 |
| $2.50 / $10 | $14.38 | $7.19 |
| $5 / $15 | $26.36 | $13.18 |

### 시사점
- 어느 단가든 저렴(최상위 단가도 Batch ~$13). 콜당 토큰 작고 추론 토큰 없음.
- 출력 비중 작아 **입력 단가가 비용 지배**.
- 파일럿(외향성 1,500쌍)은 1/5 규모.
- **정확한 값**은 gpt-5.4 실단가 확정 시 위 표에 대입. (시나리오 토큰은 chars/4 근사이나
  전체의 ~11%라 오차 작음. 쌍 생성분은 API 실측.)
